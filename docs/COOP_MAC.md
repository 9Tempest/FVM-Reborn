# 两台 Mac 异地合作

本分支提供原生 macOS 双人合作：房主的游戏负责运行战斗，合作服务把进度保存在房主 Mac 的本地数据库；队友通过加密的 WebSocket 连接加入。两人共享战役进度、卡组和战场资源，分别放置并控制自己的角色。房主负责选择关卡与卡组。

目前是实验性功能。原生网络、会话恢复、真实服务端数据库与公网 TLS 已有自动化验证；**尚未完成另一台异地 Mac 的实际联机验收，也未逐一验证所有关卡**。完整游戏的双客户端界面与战斗验收仍在进行，不能把下面的测试数字视为全部玩法已经通过。

## 开始之前

- 两台 Mac 使用包含合作功能的同一版本游戏，系统为 macOS 13 或更新版本。Apple Silicon 已实际运行；Intel 完整游戏仍待验收。
- 房主先安装并启动合作服务，保持 **Mac 醒着、已登录、联网，并让房主游戏持续运行**。后台服务不会阻止系统睡眠；合盖、休眠、退出房主游戏或断网都会影响合作。
- 队友只需游戏与邀请码，不需要安装 Python 服务或 cloudflared。两台电脑不必处于同一局域网。
- 目前的本地 `.app` 使用 ad-hoc 签名，**没有 Apple Developer ID 发布签名或 Apple 公证**，尚不是面向所有 Mac 的正式分发包。源码构建见 [macOS 构建说明](MACOS.md)；在第二台 Mac 上使用时，不能把本机成功双击启动等同于已完成另一台机器的安装验证。

## 第一次一起玩

1. **房主**打开游戏，进入准备作为合作起点的单人存档。创建房间会复制这份进度到合作战役；以后合作进度与原单人槽分开保存。
2. 在房主电脑检查服务状态，确认 `loaded` 为 `true`、`status` 为 `online`，并且 `public_url` 非空。命令见下文。服务刚启动时需等待公网连接建立。
3. 房主从主菜单点击 **「双人异地合作」→「创建合作房间」→「复制邀请码」**，把完整的 `FVM1:` 开头代码私下发给这位队友。
4. **队友**打开游戏的合作界面，点击 **「粘贴」→「加入合作房间」**。首次邀请默认约十分钟有效，只能成功使用一次。过期时，房主可退出后重连上次房间，重新复制邀请码；不要把过期代码继续转发。
5. 房间显示两位玩家均已连接后，房主点击 **「选择关卡与卡组」**，按正常流程选关、选卡并开始。队友等待房主开局。
6. 进入战场后，两人分别点击可用网格放置自己的角色。两人都放置完成且没有人请求暂停后，战斗才继续。
7. 通关或失败后，等待界面提示结果/共同进度已保存，再退出合作。若显示正在等待存档确认，先保持房主游戏与服务运行。

同一个房间固定一位房主和一位队友。队友退出或断线后席位仍保留给原身份；不能用新邀请码把第三个人替换进去。更换搭档需要创建新房间。

## 战斗操作

| 操作 | 方法 |
| --- | --- |
| 放置自己的角色 | 开局时鼠标左键点击可用网格 |
| 选卡 | 点击卡槽，或按数字键 `1`–`9` |
| 放卡 | 选卡后左键点击网格；两人共用资源和冷却，操作仍需满足地形、费用等规则 |
| 取消当前选择 | 鼠标右键 |
| 铲除或使用宝石 | 点击对应按钮后选择目标网格；适用范围按游戏规则判断 |
| 请求暂停 / 取消自己的暂停 | 空格；队友界面也支持 Esc。任意一人仍请求暂停、未放角色或离线时，战斗保持暂停 |

合作模式没有两套独立经济。房主购买、强化及战后获得的共同进度由主机保存，再同步给队友；队友发出的战斗操作由房主游戏验证后执行。

## 断线、重启与新地址

短暂断线时，游戏检测到失联后暂停战斗并自动重连。恢复同一房间会沿用各自身份和已确认进度。再次打开游戏时，点击 **「重连上次的房间」**，不要为了继续原战役反复创建新房间。

**房主游戏进程重启后，未完成战斗不能从中途完整恢复。** 当前保存的画面快照不足以重建整个模拟；重连会结束那一局未完成的战斗，再从已提交的合作进度继续。已经确认保存的升级、奖励和战役进度保留在数据库中。若只是网络中断，房主原游戏与战斗实例仍在，则走连接恢复流程。不要把退出房主游戏当作战斗中的暂停方式。

公网连接使用免费的 Cloudflare Quick Tunnel。其地址是随机生成的 `trycloudflare.com` 子域名；Cloudflare 将其定位为开发测试用途，不保证 SLA 或持续在线，并列出 200 个并发在途请求的上限。服务停止、重新启动或隧道重建后，地址可能变化。这些限制来自 [Cloudflare 官方 Quick Tunnels 说明](https://developers.cloudflare.com/cloudflare-one/networks/connectors/cloudflare-tunnel/do-more-with-tunnels/trycloudflare/)。

地址变更后的恢复方法：

1. 房主等待服务再次显示 `online`，打开或重连原合作房间。
2. 房主点击 **「复制重连码」**；仍未有队友加入的房间显示「复制邀请码」。复制时游戏会读取服务写入的最新公网地址。
3. 原队友回到加入界面，粘贴新代码后点击「加入合作房间」。必要时先退出并重新打开队友的游戏。游戏会使用这台 Mac 私下保存的原身份恢复连接。

已有两位身份时，「复制重连码」只携带房间与最新地址，不包含可邀请新人的凭据，也不包含房主的私密恢复凭据。它只能帮助保留着本地恢复凭据的原队友；无法让陌生设备冒充原队友。请保留各自的游戏数据目录。

Quick Tunnel 的随机地址不是永久服务器地址。当前实现没有购买域名、创建付费服务或配置固定域名隧道。

## 房主服务的管理

以下命令在仓库根目录执行。初次安装需要 Python 3.11+、独立环境和正确的游戏存档目录，完整安装步骤见 [服务端说明](../server/README.md#optional-mac-login-service-and-free-external-connectivity)。运行过 `server/setup.sh` 后，使用其独立 Python：

```sh
# 查看运行状态和当前公网地址；不输出访问凭据。
server/.venv/bin/python server/manage.py status

# 启动，并恢复当前 macOS 用户登录后的自动启动。
server/.venv/bin/python server/manage.py start

# 停止服务，同时关闭该用户的登录自动启动；保留数据。
server/.venv/bin/python server/manage.py stop
```

`start` 在服务已运行时不会重启。`stop` 会中断正在进行的连接，先完成结算并退出合作。服务由当前用户的 LaunchAgent 管理，不需要管理员权限；其名字为 `io.github.9tempest.fvmreborn.coop`。源代码更新后，应按服务端说明重新执行安装，以更新已经复制到应用数据目录的服务代码。

默认使用以下位置：

| 内容 | 位置 |
| --- | --- |
| 合作数据库 | `~/Library/Application Support/FVM-Reborn/co-op/coop.sqlite3` |
| 合作数据库备份 | `~/Library/Application Support/FVM-Reborn/co-op/backups/` |
| 服务状态、日志、独立 Python 与已安装服务代码 | `~/Library/Application Support/FVM-Reborn/co-op/` |
| 登录服务定义 | `~/Library/LaunchAgents/io.github.9tempest.fvmreborn.coop.plist` |
| 本机游戏的合作连接配置与恢复请求 | 游戏实际存档目录内的 `coop/`；位于该应用的 macOS 沙盒容器中 |
| 原单人档 | 游戏实际存档目录内的 `saves/`，仍使用原存档槽 |

这里指 `manage.py install` 管理的服务；直接运行开发用 `server/run.sh` 的默认数据目录不同。游戏存档目录应使用安装时确认的实际 `save_directory`，不要把源码目录当作存档目录。已安装服务的 `launcher.json` 记录了该路径。

合作数据库与备份都保存在房主电脑，并非云端存档或异地备份。服务默认每五分钟及正常停止时创建数据库备份，保留最近 48 份。备份、迁移和恢复细节见 [服务端持久化说明](../server/README.md#security-durability-and-operational-limits)。不要在服务运行中直接覆盖 SQLite 文件。

原单人存档在进入合作前先保存；合作期间使用独立的共同进度，退出后恢复原单人状态。`host-token`、游戏 `coop/host.json` 与 `coop/session.json` 含本机私密凭据，不应贴进聊天、提交到 Git，或作为邀请码发送。给队友分享游戏内复制的代码即可。

## 已验证范围

验证环境为 macOS 14.5 / Apple Silicon，GameMaker Runtime 2026.0.0.23：

- 原生 WebSocket 传输：25/25，包含中文、较长文本、标准消息帧、超时与重连。
- 真实 Python 服务端与原生双连接：28/28，包含建房、加入、输入去重、结果去重、恢复与 SQLite 持久化。
- 真实 `CoopSession` 原生测试：54/54，包含磁盘失败不提前提交、待确认请求恢复、进度防回滚、单人档隔离、客人恢复与新地址码。
- 公网 WSS：10/10，包含原生 TLS、实际 Session 握手、无凭据和错误凭据拒绝；该测试未创建真实玩家房间。
- Python 服务端：10/10，包含双人事务回滚、进程重启恢复、重复结算防重奖、应用层心跳与静默连接超时。
- 本机后台服务停止/启动与公网地址自动更新已验证。

连接使用每五秒一次的 JSON `ping/pong`；已登录客户端连续 30 秒没有应用消息时，服务端会断开连接。已验证的 GameMaker Runtime 对标准 WebSocket control PING 回复了未正确 masking 的 PONG，因此服务端停用主动 control PING，保留标准消息帧校验。该调整与游戏的后台调度优化是两项独立修复。

这些测试使用隔离数据和最小原生工程；会话测试中的游戏画面、存档格式校验和战斗回调使用测试替身。它们验证网络和会话边界，不替代两台实际 Mac 的完整游玩验收。复现命令与技术说明见 [原生联机测试说明](../scripts/CoopTransport/README.md)。
